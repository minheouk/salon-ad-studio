# src/pipelines/serving/mock (목업 API)

진짜 모델 대신 **정해진 형식의 가짜 결과를 돌려주는 API**입니다.
모델이 완성되기 전에도 서비스 개발이 화면을 만들고 연결해 볼 수 있게 합니다.

- 결과 이미지는 단색 PNG(1024×1024)입니다. 가격표 이미지는 짙은 회색, 네일 팁 이미지는 여러 색입니다.
- 광고 문구는 `[목업]`으로 시작하고, 받은 매장명·인스타그램 계정명·영업시간·예약 링크를 그대로 넣은 고정 문구입니다.
- 실제 모델은 이미지는 **GPT Image 2**, 광고 문구는 **GPT6 LUNA**를 쓸 예정입니다. 목업은 모델을 호출하지 않으므로 API 비용이 들지 않습니다.
- 받은 사진과 요청 내용은 메모리에서만 쓰고 **디스크에 저장하지 않습니다.** 회원 정보는 백엔드에서 관리합니다.
- Python 표준 라이브러리만 씁니다. 따로 설치할 패키지가 없습니다.

## 실행하기

저장소 루트에서 실행합니다. `--port`에는 [VM 가이드](../../../../docs/vm_member_guide.md)에 있는 **본인 API 포트**(`800N`)를 넣습니다.

```sh
python3 -m src.pipelines.serving.mock.server --port 8004
```

- 서버는 `127.0.0.1`에서만 받습니다. **외부에 포트를 열지 않습니다.** VM에서 띄웠다면 SSH 포트 전달로 내 PC에서 접속합니다.
- 팀 VM에서 오래 켜 둘 때는 `tmux` 안에서 실행합니다. `Ctrl+B`를 누른 뒤 `D`를 누르면 서버는 켜 둔 채로 빠져나옵니다.
- 종료는 실행한 터미널에서 `Ctrl+C`를 누릅니다. 결과는 메모리에만 있어서 서버를 끄면 모두 사라집니다.

## 웹 백엔드에서 연결하기

| 용도 | `AI_BASE_URL` |
|---|---|
| 개발·목업 연결 | `http://127.0.0.1:8004` |
| 통합 테스트·시연 | `http://127.0.0.1:8000` (팀 공용 데모 포트, 쓰기 전에 디스코드에 공지) |

- 웹 백엔드가 **팀 VM 안에서** 실행된다는 전제입니다. VM 밖에서 실행되면 이 주소로는 접근할 수 없어서, 연결 방법을 PM과 따로 정해야 합니다.
- 공통 경로는 없습니다. `{AI_BASE_URL}/generate`, `{AI_BASE_URL}/edit`, `{AI_BASE_URL}/copy`로 부릅니다. 결과 다운로드는 응답의 `url`을 `AI_BASE_URL` 뒤에 붙여 `GET`합니다.
- **인증 헤더는 없습니다.** VM 안과 SSH 연결로만 접근할 수 있어서 이미 막혀 있습니다. 사용자의 Supabase 토큰은 AI 서버로 보내지 않습니다.

### 내 PC에서 시험하기

- **VS Code Remote-SSH**로 VM에 접속해 있으면 포트가 자동으로 연결됩니다. 내 PC에서 같은 번호를 이미 쓰고 있으면 다른 번호(예: 8005)로 연결되니, VS Code 아래 패널의 **포트** 탭에서 "전달된 주소"를 확인합니다.
- **VS Code 없이**: 내 PC의 PowerShell에서 실행하고, 그 창을 켜 둔 채 `http://localhost:8004`로 부릅니다. VM 이름·zone·프로젝트 ID는 디스코드 VM 공지에 있습니다.

  ```powershell
  gcloud compute ssh <VM_NAME> --zone <ZONE> --project <PROJECT_ID> --ssh-flag="-N" --ssh-flag="-L 8004:127.0.0.1:8004"
  ```

  - VM 안에서 실행하면 권한 오류가 납니다. 반드시 **내 PC**에서 실행합니다.
  - PowerShell은 `--`를 지워 버려서 `-- -N -L ...` 형식이 안 됩니다. `--ssh-flag`로 넘깁니다.
- **연결 확인**: `http://localhost:<포트>/`를 열어 `{"error": {"code": "NOT_FOUND", ...}}`가 보이면 정상입니다. 계속 로딩되거나 연결이 끊기면 VM에서 목업 서버가 꺼져 있는 것입니다.

## 전체 흐름

**동기 방식**입니다. 생성 요청을 보내면 처리가 끝날 때까지 기다렸다가, 같은 요청의 응답으로 최종 결과를 돌려줍니다.

```
1. POST /generate              → 이미지 생성. 처리가 끝날 때까지 대기 (목업은 3초)
2. 200 응답의 results[].url     → 이미지를 바로 내려받아 웹 백엔드가 보관 (GET)
   실패(502)·시간 초과(504)·대기열 가득(429) → 사용자가 다시 시도할 때만 같은 요청을 다시 보냄
3. 결과 수정 단계               → POST /edit: 이미지 1장씩 수정, 응답의 result.url로 내려받음
4. 게시 미리보기                 → POST /copy: 고른 최종 이미지로 광고 문구 생성
```

- **결과 수정 단계에서는 이미지만 다룹니다.** 광고 문구는 만들지 않습니다.
- **광고 문구는 게시 미리보기에서 만듭니다.** 사용자가 게시할 이미지를 다 고른 뒤 웹 백엔드가 `/copy`를 따로 부릅니다.
  - 순서만 바뀌면 문구를 그대로 쓰고, 이미지 구성이 바뀌면 사용자가 다시 만들지 고를 수 있습니다 (웹에서 판단).
- 상태 조회, 취소, 재시도 API는 없습니다.

### 재시도

- **서빙도 웹 백엔드도 자동으로 재시도하지 않습니다.** 429·502·504를 받으면 사용자가 다시 시도할 때만 같은 요청을 보냅니다.
  - 실제 모델은 외부 API를 부르기 때문에, 504를 보낸 뒤에도 이미 보낸 호출은 멈출 수 없어서 비용이 나갈 수 있습니다. 자동으로 다시 보내면 비용이 두 번 나갑니다.
- **429 `QUEUE_FULL`**: `Retry-After`(10초)가 지난 뒤에 다시 시도할 수 있게 합니다.
- **504 `TIMEOUT`**: 서빙은 그 요청의 처리를 끝내고 결과를 버립니다. 다시 보내도 결과가 두 번 만들어지지 않습니다.
  - 웹 백엔드는 이 코드를 사용자에게 `504 GENERATION_TIMEOUT`으로 바꿔 보냅니다. 웹 자체 70초 대기를 넘긴 경우도 같은 코드입니다.
- **광고 문구(`/copy`)만 실패한 경우**: 고른 이미지와 순서는 그대로 두고 `/copy`만 다시 요청합니다.
- 생성은 **한 번에 하나씩 순서대로** 처리합니다. 이미지 생성·수정·광고 문구 요청은 같은 대기열을 씁니다.

## 광고 생성: `POST /generate`

웹 백엔드가 받은 사진 1장을 **파일 그대로(바이너리)** `multipart/form-data`의 `images` 필드로 보냅니다.
요청 필드는 [API 명세](https://docs.google.com/spreadsheets/d/1W98YYAuxcuiWkDYRTW-1GSuWUvfxa46Vk8d0J77EFus/edit?gid=882937156#gid=882937156)의 AI-01과 같습니다.

```sh
curl -X POST http://127.0.0.1:8004/generate \
  -F "shop=오라네일" \
  -F "instagramId=ora_nail" \
  -F "businessHours=화~일 11:00–20:00 / 월 휴무" \
  -F "booking=https://example.com/reserve" \
  -F "prompt=겨울 분위기의 12월 이달의 아트를 만들어 주세요." \
  -F "images=@winter-nail.jpg"
```

| 필드 | 규칙 |
|---|---|
| `images` | 정확히 1장, PNG 또는 JPG, 10MB 이하 |
| `prompt` | 필수. 앞뒤 공백을 뺀 뒤 1~200자. 비어 있으면 `400 EMPTY_PROMPT` |
| `shop`, `instagramId`, `businessHours`, `booking` | `/generate`에서는 받기만 하고 쓰지 않습니다. 형식 검사는 웹 백엔드가 합니다 |

- **실험 환경에서는 빈 값과 이미지 미첨부를 허용하지만, 실제 서비스는 모든 필드가 필수이고 빈 값을 받지 않습니다.** 목업은 실제 서비스 규칙을 따릅니다.

- 받은 사진은 검사와 생성에만 쓰고 **저장하지 않습니다.**
- 결과 이미지는 **최대 13장**입니다. 가격표가 붙은 이미지(`price_table`) 1장이 항상 맨 앞에 오고, 네일 팁 이미지(`nail_tip`)가 최대 12장 뒤에 붙습니다. 목업은 항상 13장을 돌려줍니다.

### 정상 응답 (`200`)

```json
{
  "generation_id": "3f2a...",
  "timing_ms": {"wait": 2, "run": 3001, "total": 3003},
  "results": [
    {"type": "price_table", "url": "/api/results/3f2a.../1?expires=...&signature=..."},
    {"type": "nail_tip", "url": "/api/results/3f2a.../2?expires=...&signature=..."}
  ],
  "results_expire_in_seconds": 86400
}
```

### 실패·시간 초과 화면 시험하기

목업은 모델을 부르지 않아서 보통은 항상 성공합니다.
실패 화면을 확인하려면 `prompt`에 아래 표시를 넣으면 됩니다.

| `prompt`에 넣을 표시 | 응답 |
|---|---|
| `[mock:failed]` | `502 GENERATION_FAILED`, `광고를 만들지 못했습니다. 다시 시도해 주세요.` |
| `[mock:timeout]` | `504 TIMEOUT`, `처리 시간이 60초를 넘었습니다. 다시 시도해 주세요.` |

예: `prompt=겨울 네일 광고 [mock:failed]`

- 60초를 기다리지 않도록, 다른 요청처럼 **3초 뒤에** 응답합니다.
- `/generate`, `/edit`, `/copy` 모두 됩니다. `/edit`은 `prompt`와 `imagePrompt` 어느 쪽에 넣어도 됩니다.
- 실패 문구는 `/edit`이 `광고를 수정하지 못했습니다. 다시 시도해 주세요.`, `/copy`가 `광고 문구를 만들지 못했습니다. 다시 시도해 주세요.`입니다.
- 표시도 200자 제한에 포함됩니다.
- **목업 전용 기능입니다.** 실제 서빙 API에는 넣지 않습니다.

### 처리 시간 (`timing_ms`)

| 항목 | 범위 |
|---|---|
| `wait` | 요청을 받은 때부터 처리 시작까지 (앞 요청을 기다린 시간) |
| `run` | 처리 시작부터 끝까지 (실제 API에서는 모델 추론 시간) |
| `total` | 요청을 받은 때부터 끝까지 = `wait` + `run` |

- 서버가 요청 본문을 다 받은 뒤부터 잽니다. 업로드·다운로드 같은 **네트워크 시간은 들어가지 않습니다.** 사용자가 체감하는 전체 시간은 웹에서 재면 됩니다.

## 광고 이미지 수정: `POST /edit`

API 명세의 AI-02입니다. **결과 수정 단계에서** 웹 백엔드가 부릅니다. 이미지만 수정하고 광고 문구는 만들지 않습니다.
수정할 이미지 1장을 보내면 수정본 1장을 돌려줍니다. 여러 장을 고칠 때는 앞 요청의 응답을 받은 뒤 다음 이미지를 보냅니다.

```sh
curl -X POST http://127.0.0.1:8004/edit \
  -F "prompt=전체 배경을 더 밝게 바꿔 주세요." \
  -F "imagePrompt=이 이미지는 글자를 더 크게 해 주세요." \
  -F "images=@result-2.png"
```

| 필드 | 규칙 |
|---|---|
| `images` | 수정할 이미지 정확히 1장. 웹 백엔드가 보관한 결과 파일. PNG 또는 JPG, 10MB 이하 |
| `prompt` | 공통 프롬프트. 여러 장에 똑같이 적용할 수정 내용 |
| `imagePrompt` | 개별 프롬프트. 이 이미지에만 적용할 수정 내용 |

- `prompt`와 `imagePrompt` 중 **하나 이상**을 보냅니다. 둘 다 없으면 `400 EMPTY_PROMPT`(`field`: `prompt`)입니다.
- 보낸 값은 `/generate`의 `prompt`와 같은 규칙(앞뒤 공백을 뺀 뒤 1~200자)으로 검사합니다. 보냈는데 비어 있으면 `400 EMPTY_PROMPT`이고, `field`에 그 필드 이름이 들어갑니다.
- 연속 수정 3회 제한(`EDIT_LIMIT_EXCEEDED`)은 웹 백엔드가 검사합니다. 서빙은 이전 수정 횟수를 기억하지 않습니다.
- **수정 대상은 네일 팁 이미지만입니다.** 가격표 수정 지원 여부는 모델팀 확인 대기입니다.
  - 가격표는 한글 문구와 가격을 이미지 위에 합성해서 만듭니다. 이미지 수정 모델로 고치면 글자가 깨질 수 있어서, 고칠 수 있게 되더라도 가격·문구를 바꿔 다시 합성하는 별도 방식이 될 수 있습니다.
  - 목업은 이미지 종류를 구분하지 않아 가격표를 보내도 수정본을 돌려줍니다. 화면 시험용 동작입니다.

정상 응답 (`200`). `/generate`처럼 다운로드 주소를 돌려줍니다. 수정본은 1장이라 `results` 목록 대신 `result` 하나입니다.

```json
{
  "generation_id": "7b1c...",
  "timing_ms": {"wait": 0, "run": 3001, "total": 3001},
  "result": {"url": "/api/results/7b1c.../1?expires=...&signature=..."},
  "results_expire_in_seconds": 86400
}
```

- 목업의 수정본은 흰색 PNG(1024×1024)입니다. 화면에서 원래 이미지와 바뀐 것을 바로 알아볼 수 있습니다.
- 이미지 종류(`price_table`·`nail_tip`)는 보낸 쪽이 알고 있어서 응답에 넣지 않습니다.
- 다운로드, 24시간 보관, 오류 응답은 `/generate`와 같습니다.

## 광고 문구 생성: `POST /copy`

API 명세의 AI-03입니다. **게시 미리보기에서** 웹 백엔드가 부릅니다.
원본 사진이 아니라, 사용자가 **실제로 게시할 최종 이미지 파일만 게시 순서대로** 한 요청에 담아 보냅니다.

```sh
curl -X POST http://127.0.0.1:8004/copy \
  -F "shop=오라네일" \
  -F "instagramId=ora_nail" \
  -F "businessHours=화~일 11:00–20:00 / 월 휴무" \
  -F "booking=https://example.com/reserve" \
  -F "prompt=겨울 분위기의 12월 이달의 아트를 만들어 주세요." \
  -F "editPrompts=배경을 더 밝게 바꿔 주세요." \
  -F "images=@final-1.png" \
  -F "images=@final-2.png"
```

| 필드 | 규칙 |
|---|---|
| `images` | 게시할 최종 이미지, 게시 순서대로 1~13장 (임시). 장마다 PNG 또는 JPG, 10MB 이하 |
| `prompt` | 필수. 최초 생성 프롬프트. 규칙은 `/generate`와 같습니다 |
| `editPrompts` | 결과 수정 단계에서 쓴 수정 프롬프트. 수정한 만큼 같은 이름으로 여러 번 보냅니다. 수정하지 않았으면 보내지 않습니다. 보낸 값은 `prompt`와 같은 규칙(1~200자)으로 검사합니다 |
| `shop`, `instagramId`, `businessHours`, `booking` | 채팅에 저장된 매장 정보. 게시글 본문(`caption`)에 모두 들어갑니다. 형식 검사는 웹 백엔드가 합니다 |

- 요청 전체 한도는 13장 × 10MB + 1MB(텍스트 여유)입니다. 장수·용량과 함께 임시 값입니다.

정상 응답 (`200`). 다운로드할 파일이 없어서 문구를 응답에 바로 담습니다.

```json
{
  "timing_ms": {"wait": 0, "run": 3001, "total": 3001},
  "caption": "[목업] 오라네일 이달의 아트\n인스타그램 @ora_nail\n영업시간 화~일 11:00–20:00 / 월 휴무\n예약 https://example.com/reserve",
  "hashtags": "#목업 #이달의아트 #오라네일"
}
```

오류 응답 형식은 `POST /generate`와 같습니다. 이미지 장수가 1~13장이 아니면 `400 PHOTO_COUNT`, 수정 프롬프트가 비어 있으면 `400 EMPTY_PROMPT`(`field`: `editPrompts`)입니다.

## 시간 초과

| 구분 | 상한 | 기준 |
|---|---|---|
| 서버 | **60초** | 요청을 받은 때부터. 앞 요청을 기다린 시간도 포함합니다. 넘으면 `504 TIMEOUT`으로 응답합니다 |
| 웹 호출 | **70초** | 웹 백엔드가 요청을 보낸 때부터. 이때까지 응답이 없으면 웹에서 포기합니다 |

서버 상한(60초)이 웹 제한(70초)보다 짧기 때문에, 웹은 포기하기 전에 항상 서버의 응답을 받을 수 있습니다.

## 동시 요청

- 생성은 한 번에 하나만 처리하고, 나머지는 순서대로 기다립니다.
- **처리 중 1개 + 대기 2개**, 모두 3개까지 받습니다. 그 이상이면 새 요청을 바로 거절합니다.

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 10

{"error": {"code": "QUEUE_FULL", "field": null, "message": "지금 처리 중인 요청이 많습니다. 잠시 후 다시 시도해 주세요."}}
```

대기를 길게 두지 않은 이유는, 순차 처리에서 앞에 요청이 많이 쌓이면 서버 상한 60초 안에 끝나기 어렵기 때문입니다.

## 결과 다운로드와 보관

- `results[].url`은 **서명 URL**입니다. `GET`으로 받으면 PNG 파일이 옵니다. 서버 주소 뒤에 붙여서 씁니다.
  - 개인정보 보호를 위해 **공개 URL은 쓰지 않습니다.** 외부 저장소(S3 등)에 올리지 않고, 결과는 이 서버 안에만 있습니다.
  - 이 주소는 서버 안의 경로라서, `127.0.0.1` 서버에 연결된 쪽(SSH 포트 전달, VM 안의 웹 백엔드)에서만 열립니다. 사용자에게는 웹 백엔드가 받아서 전달합니다.
  - 결과를 다시 조회하는 API가 없으므로, 주소는 결과 보관 기간과 같은 **24시간 동안 유효합니다.** 만료되면 `403 URL_EXPIRED`가 옵니다.
  - 주소를 고치면 `403 INVALID_SIGNATURE`가 옵니다.
- 서버는 결과를 **만든 시점부터 24시간** 보관합니다. `results_expire_in_seconds`가 남은 시간입니다. 지나면 `404 RESULT_NOT_FOUND`가 옵니다.
- 서명 키는 서버를 켤 때마다 새로 만들기 때문에, 서버를 다시 켜면 이전 주소는 모두 무효가 됩니다.

## 실패 응답

실패하면 HTTP 상태 번호와 함께 `error` 안에 `code`, `field`, `message`를 돌려줍니다. 웹 탭(WEB-xx)의 오류 형식과 같습니다.
- 웹에서는 **HTTP 상태 번호로 입력 오류(4xx)인지 판단**하고, `code`로 분기합니다.
- `field`는 문제가 된 요청 필드 이름(`images`, `prompt`, `imagePrompt`, `editPrompts`)입니다. 필드와 관계없는 오류는 `null`입니다.
- `message`는 사용자에게 그대로 보여 주면 됩니다.

```json
{"error": {"code": "PROMPT_TOO_LONG", "field": "prompt", "message": "요청 내용은 200자 이하로 입력해 주세요."}}
```

**입력 오류**: 생성 전에 거절합니다.

| HTTP | `code` | `field` | 언제 |
|---|---|---|---|
| 400 | `EMPTY_PROMPT` | `prompt`, `imagePrompt`, `editPrompts` | 앞뒤 공백을 빼면 비어 있음. `/edit`은 두 프롬프트가 모두 없을 때도 |
| 400 | `PROMPT_TOO_LONG` | `prompt`, `imagePrompt`, `editPrompts` | 요청 내용이 200자를 넘음 |
| 400 | `PHOTO_COUNT` | `images` | `/generate`·`/edit`: 이미지가 1장이 아님 / `/copy`: 이미지가 1~13장이 아님 |
| 400 | `UNSUPPORTED_FORMAT` | `images` | 파일 내용이 PNG·JPG가 아님 |
| 400 | `FILE_TOO_LARGE` | `images` | 사진 한 장이 10MB를 넘음 |
| 400 | `BROKEN_IMAGE` | `images` | 파일이 손상됨 (아래 참고) |
| 400 | `RESOLUTION_TOO_LOW` | `images` | 짧은 변이 512px 미만 |
| 400 | `RESOLUTION_TOO_HIGH` | `images` | 긴 변이 8192px 초과 |
| 413 | `BODY_TOO_LARGE` | `null` | 요청 전체가 한도를 넘음. `/generate`·`/edit` 11MB(사진 10MB + 텍스트 여유 1MB), `/copy` 131MB(13장 × 10MB + 1MB, 임시) |
| 415 | `INVALID_FORM` | `null` | `Content-Type`이 `multipart/form-data`가 아님 |

여러 장 중 하나가 문제면 `message`에 몇 번째 사진인지 적어 줍니다. 예: `2번째 사진 파일이 손상되었습니다.`

**생성·결과 관련 오류**: `field`는 모두 `null`입니다.

| HTTP | `code` | 언제 |
|---|---|---|
| 502 | `GENERATION_FAILED` | 모델이 광고를 만들거나 수정하지 못함 |
| 504 | `TIMEOUT` | 요청을 받은 때부터 60초가 넘음 (웹 백엔드가 `GENERATION_TIMEOUT`으로 바꿔 보냄) |
| 429 | `QUEUE_FULL` | 처리 중·대기 중 요청이 가득 참 (`Retry-After` 헤더 포함) |
| 403 | `INVALID_SIGNATURE` | 다운로드 주소가 올바르지 않음 |
| 403 | `URL_EXPIRED` | 다운로드 주소의 24시간이 지남 |
| 404 | `RESULT_NOT_FOUND` | 없는 결과이거나 24시간 보관이 끝남 |
| 404 | `NOT_FOUND` | 없는 주소 |

## 손상된 파일과 해상도 처리

이미지 라이브러리 없이 **파일 구조만 읽어서** 검사합니다.

- **형식은 파일 내용으로 판별합니다.** 파일 이름이나 `Content-Type` 표기는 믿지 않습니다. 예를 들어 이름만 `.jpg`인 다른 파일은 `UNSUPPORTED_FORMAT`이 됩니다.
- **PNG**: 모든 청크의 CRC(검사값)를 확인하고, 끝 표시(`IEND`)까지 있어야 통과합니다. 업로드 중 잘린 파일이나 중간이 깨진 파일이 여기서 걸립니다.
- **JPG**: 끝 표시(`EOI`)가 있어야 하고, 본문 전에 해상도 정보(`SOF`)가 있어야 통과합니다.
- **해상도 기준**
  - **최소: 짧은 변 512px.** 이보다 작으면 광고 이미지로 쓰기에 화질이 부족합니다.
  - **최대: 긴 변 8192px.** 일반 휴대폰 사진(12MP, 4032×3024)은 통과합니다. 48MP 이상의 고해상도 원본만 막습니다.
- **한계**: 구조 검사라서 화소 데이터 안쪽이 깨진 경우까지는 잡지 못합니다. 실제 서빙 API에서는 이미지를 열어 보는 디코딩 검사를 더하고, 최대 해상도 이하의 큰 사진은 거절하지 않고 모델 입력 크기로 줄이는 방식을 권장합니다.

## 정해지지 않은 것

- **요청 전체 최대 용량**: `/generate`는 사진 1장 10MB를 기준으로 임시로 정했습니다.
- **`/copy` 요청 형식**: 이미지 필드 이름(`images`), 최대 장수(13장), 장당·전체 용량, 전송 형식(`multipart/form-data`), 수정 프롬프트 필드 이름(`editPrompts`)은 모두 임시입니다. 최종 작업 후 서비스팀과 맞춥니다.
- **결과 이미지 ID**: `results[]`에 넣을 이미지 ID의 필드 이름과 형식은 아직 정해지지 않아 목업에 넣지 않았습니다.
- **네일 팁 이미지 수**: 실제 모델이 몇 장(최대 12장)을 만들지 정해지면 맞춥니다. 목업은 항상 12장입니다.
- **대기 가능한 요청 수**: 처리 중 1개와 대기 2개는 임시로 정한 값입니다.
- **`/edit` 요청 형식**: 개별 프롬프트 필드 이름(`imagePrompt`)과, 공통·개별 프롬프트가 부딪힐 때의 우선순위는 임시입니다. 모델팀이 수정 기능 지원 여부와 입력 형식을 확인하면 맞춥니다.
- **결과 파일 저장 위치**: 목업은 메모리에 둡니다. 실제 서버는 24시간 보관할 곳(`outputs/` 등, 커밋 금지)을 정해야 합니다.
- **5초 동영상**: 지원 여부가 정해지면 추가합니다.
- **이 요청·응답 형식은 아직 서빙 쪽 제안입니다.** 서비스·모델 담당과 합의하면 `src/common/`에 정의합니다. `src/common/`은 공용 파일이라 PM 승인이 필요합니다.
